# EPIC-02.7 产品信息架构候选

用途：定义视觉方向共用的完整产品壳层，不表示对应后端已实现。

## 1. 一级产品框架

| 一级模块 | 用户心智 | 二级能力 | 当前来源 |
| --- | --- | --- | --- |
| 项目 | 我们要解决什么、谁参与 | 项目中心、项目概览、成员与权限、风险与待办 | 前三项真实 API；风险与待办为原型 |

| 数据与数据库 | 用了哪些数据、结构和上下文 | 数据源与数据库实例、Schema、数据产品、质量、快照、Evidence、语义与知识、ContextManifest | 语义/知识/Context 为真实 API；其余为原型或未来能力 |
| 主 Agent 中心 | 谁贯穿项目协助人完成工作 | 主 Agent 配置、协作会话与目标、Builder 草稿、模型路由、预算、评测与审计 | 原型 / 未来能力；未接 Agent 后端 |

一级导航是产品地图，不是“所有模块都已可用”的暗示。预览中的每个入口都必须显示 `真实 API`、`混合边界` 或 `产品原型`；打开未实现模块时只展示能力清单和边界说明，不展示伪造的成功数据。

## 2. 主 Agent 与执行 Agent 必须分开

- **主 Agent** 是贯穿项目和工作室的协作层，面向项目目标、澄清、规划、Builder 草稿 diff 与解释；它不是画布执行节点，没有 DATA/CONTROL 端口，不参与具体执行，也不继承执行节点的 Skill/MCP。
- **执行 Agent** 位于“Agent 与能力”目录，并可作为工作流 typed node 被装配；每个节点实例分别持有模型、SkillBinding、McpBinding、Scope、预算、重试和失败出口，不得隐式跨节点共享。
- `Skill / MCP` 在节点库的“能力”分区中只能装配到已选执行 Agent，不能作为主 Agent 独占能力，也不能用“＋节点”暗示直接落到画布执行。
- 阶段 B 原型包含三个装配不同的执行 Agent 节点，并在主 Agent 面板持续显示“无执行端口 / 未调用模型 / 未写入后端”。

## 3. 数据与数据库边界

数据区不能只等同于上传文件，也不能把现有 Semantic/Knowledge API 误称为完整数据库管理。建议结构为：

```text
数据与数据库
├─ 连接：数据源 / 数据库实例 / 凭据引用
├─ 结构：Catalog / Schema / 表 / 字段 / 血缘
├─ 产品：数据产品 / 负责人 / SLA / 质量规则
├─ 证据：快照 / Evidence / ContextManifest
└─ 语义：术语 / 映射 / 知识版本
```

当前只有语义、知识和 ContextManifest 的真实 API。连接、Catalog、Schema、质量、血缘和快照均只作为产品框架候选，不能收集凭据、连接数据库或显示伪造健康状态。

## 4. 真实页面迁移关系

- `/` 保持现有真实治理页面和 API 行为，不被方向预览替换；
- Project 页面未来落入“项目”；Membership 与 Audit 分别被“项目”和“治理”引用，但后端授权不变；
- Registry / Installation / DomainLock 落入“领域”；Semantic / Knowledge / Context 落入“数据与数据库”；
- 工作流、运行、主 Agent 与执行 Agent 目前只有隔离原型入口，均不调用 `/v1` 或 `/health`。
